# Архитектура Macseed — краткий обзор

Этот обзор помогает ориентироваться в проекте; он не является второй технической
спецификацией. Авторитетный документ — [Macseed Architecture](../toolkit/ARCHITECTURE.md).
Точные форматы и поведение определяют английские references из
[оглавления документации](../README.md).

## Один Core, два интерфейса

Macseed восстанавливает поддерживаемое состояние окружения:
**Capture → Rebuild → Verify**. Core/CLI **3.4.0** включает завершённый Protocol V1.
Нативный SwiftUI Desktop уже выполняет Capture, Restore и read-only Environment
Status; Stage 16 остаётся в разработке. Secure SSH в Desktop, оставшаяся
квалификация runtime/recovery и packaged clean-Mac проверки ещё не завершены.

```text
                         Core (Bash / Python)
       Discovery · Selection / Blueprint · Preview · Bootstrap
          Verification · Comparison · Bundle · Secure Migration
                          /             \
              CLI: bs / bootstrap.sh    Protocol V1 → SwiftUI Desktop
```

Core владеет наблюдением, планированием, изменением и проверкой состояния.
CLI предоставляет команды/подтверждения в терминале. Desktop управляет нативным
интерфейсом и отображает структурированные результаты Core; он не разбирает
терминальные логи и не реализует второй Restore/Verification engine.
Текущая структура Bash/Python-модулей сохраняется.

## Данные и основной поток

1. **Discovery** наблюдает только поддерживаемый домен и публикует локальные
   производные данные в `config/generated/` после сбора и проверки.
2. **Blueprint** выбирает категории/элементы, не заменяя обнаруженные значения.
   Данные читаются штатными парсерами, никогда через `source` или `eval`.
3. **Preview** проверяет выбранные требования без Apply, установки инструментов
   или запроса административной авторизации.
4. **Bootstrap / Restore** валидирует входы до первой мутации, наблюдает текущее
   состояние и следует **Check → Apply → Verify**. Совпадающее состояние — no-op;
   ошибка наблюдения не означает отсутствие и не разрешает запись.
5. **Global Verification** сообщает соответствие выбранным требованиям и пробелы
   покрытия независимо от exit code операции. **Comparison** запускается явно,
   только читает состояние и не планирует удаление лишнего.

Capture создаёт приватный Saved Environment (`.mbt`) через staging, не заменяя
обычные Generated Configuration/Blueprint исходного Mac. Restore проверяет Bundle,
сужает выбор, показывает Preview и после подтверждения выполняет Core-план.
Execute повторно проверяет подготовку и отвергает устаревший план до публикации.
Prepared ID не является авторизацией или транзакцией.

## Границы восстановления

Приложения получают заново, репозитории клонируют из remotes, поддерживаемые
настройки восстанавливают. Workspace Folders создаёт структуру, а не переносит
пользовательское содержимое. Linked-worktree topology ещё не восстанавливается;
это следующий отдельный этап [Roadmap](../../ROADMAP.md#complete-workspace--git-worktree-restoration).
Macseed не является полным клоном, backup или заменой Migration Assistant.

App Store Restore использует assisted flow: требования → ручная установка в
Apple App Store → свежая проверка Core. Подтверждённое совпадение идентичности
Cask/App Store получает Cask-first precedence; при неопределённости сохраняются
оба требования. Automatic MAS/MASHelper/XPC выведены из активного пути, исторический
архив не разрешает их повторное развёртывание. Homebrew владеет своими нативными
Install/Repair; неизвестная семантика или непроверенное владение блокирует действие.

## Безопасность и достоверность

- Конфликты сохраняют существующие данные: никаких автоматических reset/clean,
  force checkout, замены remote или удаления файлов ради схождения.
- Успех команды не доказывает Verification, работоспособность приложения, визуальный
  эффект настройки, сетевую SSH-аутентификацию или идентичность всего Mac.
- Обычный Bundle приватный, но не зашифрован; checksums не доказывают подлинность.
  SSH identities выбираются отдельно и передаются в зашифрованном `secure.age`.
- Core/CLI Secure Migration реализован; Desktop FD/challenge bridge остаётся 16H.
  Секреты не передаются через обычный JSONL, argv, environment или логи.
  Import проверяет весь пакет и не заменяет существующие конфликтующие ключи;
  выбранный secure import предшествует зависимым Workspace clones.
- Graceful Stop завершает неделимую текущую работу и останавливает последующий
  запуск. Force Stop может оставить неизвестные последствия; нет обещания rollback
  или полной остановки detached/privileged процессов.
- Повторный запуск требует свежих Prepare/Preview/подтверждения. Восстановление
  локальной публикации не откатывает установки, настройки или импортированные ключи;
  диагностический журнал не даёт полномочий на recovery или Resume.
- Desktop хранит ограниченные типизированные журналы; Diagnostic Report использует
  отдельный allowlist. Нет автоматической отправки, raw-output dump или экспорта
  приватных путей/объектов/секретов.
